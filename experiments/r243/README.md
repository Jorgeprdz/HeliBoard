# Tactic Keyboard R2.4.3 hybrid prototype
Host-only experiment; production IME unchanged. No APK until a valid linguistic gate passes.
- `HybridCandidateGenerator` reuses the existing weighted motor edit cost and accepts actual geometry, vocabulary, frequency, context and personal preference through a lexicon. Bounded one-to-three-token alternatives include spacing and valid-word alternatives; 24 outputs, 4096 distance calls, beam 12, maximum clause 256 UTF-16 units.
- All new candidates are **suggestions**, never calibrated automatic corrections. Numbers, uppercase names/acronyms, negations, commands and listed commitments cause conservative abstention. This restricts coverage, including sentence-initial uppercase typos; it does not prove semantic equivalence.
- `ClauseReviewQueue` keeps one running review plus latest pending; changed dependency keys permit reconsideration. Production `ContinuousReviewAnchor` is exercised for append/mutation. An Android caller would still have to validate editor/range/composition on delivery.
- `PrototypeBridge` runs actual R2.4.1 reviewer components, R2.4.2 focus/guard components and new candidates. It reads only external vocabulary and input, never references.
- `evaluate.py` supports real existing Qwen0.5B focused baseline and Qwen1.5B integer selection among minimal clause edits using the existing native host executable. It checks model SHA-256 and never downloads models or a runtime. It is not a claim that either model improved quality.
- Comparative scope is component-level, **not** the complete native Android IME. Automatic and assisted outputs are scored separately. A hybrid candidate can edit valid words because it is bounded and explicitly accepted; output-specific human meaning review is mandatory. The old focus baseline retains its production guard.
- Missing 100 independent human-annotated clauses and independent vocabulary is BLOCKED, not a synthetic benchmark. `corpus-contract.json` describes required provenance and 40 ES-MX / 20 EN / 10 mixed / 30 protected counts. A/B/C remain known diagnostics, never blind evidence.
- Metrics are exact character-span edit precision/recall/F0.5, missed + introduced edits, coverage and abstentions. They are not semantic metrics; human review sealed to actual output SHA-256 is required. The 20% target concerns assisted residual errors in both ES/EN; automatic quality and protected controls must not regress.
- Two human reviewers must assess all changed outputs. This small gate does not establish statistical production confidence or calibrated automatic thresholds.
- No model or independent data has been supplied for this experiment. Do not reuse vocabulary derived from reference sentences.
Run cloud component checks with `python3 experiments/r243/run_checks.py` through existing `r23-cloud.yml`, input `mode=r243-prototype`. This uses javac/JUnit/Python only; no Gradle, APK, signing or model download.
To reproduce the comparative experiment on a prepared cloud runner: compile the bridge using the source list in run_checks; run `evaluate.py --classes CLASSES --corpus corpus.json --lexicon independent.tsv --runtime writing-eval --qwen05 existing-05.gguf --qwen15 existing-15.gguf --out report.json`. Collect human reviews of the sealed outputs, then repeat with `--meaning-review reviews.json`. The models are experimental comparators, not production selection.
